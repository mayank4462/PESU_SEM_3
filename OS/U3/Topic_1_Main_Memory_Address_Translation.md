# Topic 1 — Main Memory and Address Translation

## 1. Main memory basics

- **Main memory (RAM):** Holds instructions and data required by executing processes.
- **Memory:** Conceptually, a large array of bytes, each with its own address.
- **Instruction cycle:** Fetch instruction → decode → fetch operands → execute → store result.
- The memory unit sees addresses; it does not inherently know how the program generated them.

### Basic hardware

- **Registers:** Very small, very fast storage inside the CPU.
- **Cache:** Keeps copies of useful data/instructions closer to the CPU; reduces average access time.
- **RAM:** Larger than registers/cache, but slower to access.
- **Ready queue:** Processes ready to run and waiting for CPU scheduling.

**Locality of reference**
- **Temporal locality:** Recently accessed data may be accessed again soon.
- **Spatial locality:** Nearby addresses may be accessed soon.

## 2. Uniprogramming and multiprogramming

- **Uniprogramming:** One user program is resident/executing at a time in the simplified model. CPU can be idle while the program waits for I/O.
- **Multiprogramming:** Several processes can reside in memory; when one waits for I/O, another may use the CPU.
- Multiprogramming requires memory protection so a process cannot corrupt the OS or another process.

## 3. Memory protection: base and limit registers

- **Base register / relocation register:** Starting physical address allocated to a process.
- **Limit register:** Size of the process's permitted logical address range.
- Every relevant user-mode memory access is checked by hardware.

### Formula

For a valid logical address:

`Physical address = Base + Logical address`

Validity condition:

`0 <= Logical address < Limit`

Example: Base = 14000, Limit = 1000.

- Logical address 0 → physical 14000.
- Logical address 346 → physical 14346.
- Logical address 999 → physical 14999.
- Logical address 1000 → invalid; hardware raises a protection trap.

The physical range is `Base` through `Base + Limit - 1`. **Limit is a size, not the ending physical address.**

### Privilege

- Base and limit registers are configured by the OS using privileged instructions.
- Privileged instructions execute only in kernel mode.
- User programs must not change these registers, or they could bypass protection.

## 4. Protection versus translation

- **Protection:** Prevents unauthorized memory access.
- **Translation:** Converts a logical/virtual address into a physical address.
- Translation answers “where does this address refer?” Protection answers “is this access allowed?”

## 5. Address binding

Address binding associates program instructions/data with memory addresses.

1. **Symbolic address:** Source-level name, e.g. `count`.
2. **Relocatable address:** Relative address/offset, e.g. 14 bytes from the module's start.
3. **Absolute address:** Specific address, e.g. 74014.

Example: starting address 74000 + offset 14 = absolute address 74014.

### Three binding stages

| Stage          | When                                                  | Consequence                                                                                  |
| -------------- | ----------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Compile time   | During compilation, if the starting location is known | Absolute code can be generated; changing the location may require recompilation/regeneration |
| Load time      | When the program is loaded                            | Relocatable code is adjusted to the chosen location; moving it requires reloading/relocation |
| Execution time | During execution, when memory references occur        | Process can potentially move while running; requires hardware translation support            |

## 6. Program processing

1. **Compiler/assembler:** Translates source code into object code.
2. **Linker (linkage editor):** Combines object modules and resolves external references.
3. **Loader:** Prepares the executable and places it in memory.
4. **Execution:** CPU runs instructions; the MMU translates addresses when required.

Do not confuse linking (combining modules/resolving symbols) with loading (preparing and placing the executable in memory).

## 7. Memory Management Unit (MMU)

- **MMU:** Hardware that translates addresses at run time.
- In the simple relocation-register model, the base is added to the logical address.
- Example: base 14000 + logical address 346 = physical address 14346.
- Modern systems commonly use page tables and a TLB; these are covered in the paging topic.

## 8. Logical and physical address spaces

- **Logical/virtual address:** Generated by the CPU during program execution.
- **Physical address:** Address seen by the memory hardware.
- **Logical address space:** Set of logical addresses generated by a program.
- **Physical address space:** Set of physical addresses used by its memory references.
- In the textbook model, logical and physical addresses can be the same under compile-time/load-time binding; they generally differ with execution-time binding.

## 9. Dynamic loading

- A routine is not loaded until it is called.
- Unused routines need not occupy memory.
- Useful for large programs with rarely used routines.
- Routines remain on disk in relocatable load format until needed.
- It can be implemented through program design; OS libraries can provide support.

**Dynamic loading = when code is brought into memory.**

## 10. Static versus dynamic linking

### Static linking
- Required library code is incorporated into the executable during the build/link process.
- Executables are usually larger.
- Different executables may contain duplicate copies of common library code.
- Updating a library generally does not update already-built static executables.

### Dynamic linking
- Linking to shared libraries is deferred until load time or execution time.
- A small **stub** helps locate/resolve the required library routine.
- The dynamic linker resolves the routine and transfers control to it.
- Shared libraries can reduce duplicated code and disk/memory use.
- Compatible programs may benefit from library updates, but versioning/compatibility matters.

| Static linking | Dynamic linking |
|---|---|
| Library code incorporated into executable | Shared library used at load/run time |
| Usually larger executable | Usually smaller executable |
| Less dependence on external shared libraries at run time | Compatible shared library must be available |

**Dynamic linking is not the same as dynamic loading.**

## 11. Memory-mapped files (`mmap`)

A memory-mapped file associates a file region with a process's virtual address space. The process can access mapped contents through pointers instead of repeatedly using `read()`/`write()` calls.

### Demand paging
- Mapping a file does not mean the entire file must be loaded into RAM immediately.
- Access to a non-resident page can cause a **page fault**.
- The OS arranges to make the required page available, checks permissions, and resumes execution.
- A page fault can be normal, not necessarily a program error.

### Shared and private mappings

- **`MAP_SHARED`:** Shared modifications can be visible through other mappings of the same underlying data. Write-back to persistent storage is a separate issue.
- **`MAP_PRIVATE`:** Private, Copy-on-Write semantics. Changes are not directly written back through this mapping to the underlying file and are not visible as changes to other private mappings.

### Copy-on-Write (CoW)
- Processes can initially share a physical page.
- When one process modifies it, the OS may create a private copy for that process.
- Avoids unnecessary copies when pages are not modified.
- Also used in process-creation mechanisms on many Unix-like systems.

### `mmap()` signature

```c
void *mmap(void *addr,
           size_t length,
           int prot,
           int flags,
           int fd,
           off_t offset);
```

| Parameter | Meaning |
|---|---|
| `addr` | Preferred virtual address; commonly `NULL` so the OS chooses |
| `length` | Number of bytes to map |
| `prot` | Access permissions |
| `flags` | Mapping/sharing behavior |
| `fd` | File descriptor |
| `offset` | File offset; must meet platform alignment requirements |

Common protections:
- `PROT_READ` — readable
- `PROT_WRITE` — writable
- `PROT_EXEC` — executable
- `PROT_NONE` — inaccessible

### `munmap()` and synchronization
- `munmap()` removes a mapping; it does not itself guarantee durable write-back.
- `msync()` can request synchronization of changes in a shared mapping with the underlying file.
- Check `open()` and `mmap()` return values.
- Mapping a positive-length range of an empty file may be possible, but accessing beyond valid file contents can cause a fault such as `SIGBUS` on Linux.
- A normal `open()` without creation flags fails if the file does not exist.

### Shared memory and IPC
- Processes can map the same file/shared-memory object at different virtual addresses while referring to the same physical pages.
- Memory mapping can support inter-process communication (IPC).
- Sharing memory does not automatically synchronize concurrent access; mutexes, semaphores, or other synchronization may be required.

## 12. High-yield distinctions

| Pair | Difference |
|---|---|
| Protection vs translation | Authorization vs address mapping |
| Logical vs physical address | CPU-generated address vs address used by memory hardware |
| Base vs limit | Starting physical address vs permitted logical-range size |
| Dynamic loading vs dynamic linking | When code enters memory vs when library references are resolved |
| `MAP_SHARED` vs `MAP_PRIVATE` | Shared changes vs private Copy-on-Write changes |
| `munmap()` vs `msync()` | Remove mapping vs request synchronization to file |

## 14. Quick revision

- Base + logical address = physical address, provided the address is valid.
- Valid logical address: `0 <= address < limit`.
- Hardware checks memory access; the OS configures protection registers.
- Execution-time binding requires address-translation hardware.
- Dynamic loading: load a routine only when called.
- Dynamic linking: resolve library routines at load/run time.
- Demand paging loads required pages on access.
- `MAP_SHARED` supports shared modifications; `MAP_PRIVATE` uses private Copy-on-Write semantics.
