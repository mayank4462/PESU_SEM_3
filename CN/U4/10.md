## 1. Physical Layer – Overview

The **Physical Layer is Layer 1 of the OSI model**. It is responsible for carrying raw bits across the physical communication medium.

Its central job is to convert the bit sequence produced by the Data Link Layer into physical signals that can travel through a medium, and to recover the bits at the receiving end.

Examples of physical media shown in the slides:
- Copper wires – carry electrical signals.
- Optical fibre – carries light signals.
- Wireless medium – carries radio signals.

> [!important] Core distinction
> The Physical Layer deals with **bits and signals**. The Data Link Layer deals with **frames**. The Physical Layer does not interpret the meaning of the data; it transports the signal representation of the bits.

## 2. OSI Reference Model and Physical Layer (Slide 3)

The OSI model contains seven layers:

| Layer | Name | Main role (context for the diagram) |
|---:|---|---|
| 7 | Application | Network services used by applications |
| 6 | Presentation | Data representation |
| 5 | Session | Session management |
| 4 | Transport | Process-to-process transport |
| 3 | Network | Delivery across interconnected networks |
| 2 | Data Link | Node-to-node delivery over a link; framing |
| 1 | Physical | Transmission of bits as signals |

### What the slide's diagram demonstrates

- **Device A and Device B** are end systems and contain all seven layers.
- The **intermediate nodes** shown contain Network, Data Link and Physical layers. They forward traffic; they do not run the end hosts' application, presentation, session or transport functions in this diagram.
- At the end systems, the corresponding layers communicate logically with their peer layers.
- Across each individual link, communication is physically carried out by the Physical Layer. The Data Link Layer handles a frame across an adjacent link; the Network Layer provides the logical path across multiple networks.
- The slide groups Layers 3–7 as implemented in software and Layers 1–2 as implemented in hardware. This is the grouping used by this particular diagram; actual implementations can combine hardware and software.

> [!tip] Remember
> Physical communication is **hop-by-hop** over each physical link. The higher-layer peer communication shown between Device A and Device B is logical communication, not one continuous physical cable between the two devices.

**Main purpose:** provide the physical means by which devices and networks can transmit signals to one another.

## 4. Physical Layer Services (Slides 5–6)

### 4.1 Main services

The role of the Physical Layer is to:

1. **Encode binary digits:** convert the binary digits representing Data Link Layer frames into signals.
2. **Transmit signals:** carry the encoded signals across the physical medium.
3. **Receive signals:** detect incoming signals and recover the represented bits.

The physical medium conducts signals in the form of voltage, light or radio waves from one device to another.

### 4.2 Analog and digital signals

| Signal | Meaning | Values |
|---|---|---|
| Analog | Continuous-valued signal | Can vary continuously in amplitude, frequency or phase |
| Digital | Discrete-valued signal | Represents discrete values such as 0 and 1 |

The slide's graph contrasts a smoothly varying analog waveform with a digital waveform that changes between discrete levels.

### 4.3 Medium and signal type

| Physical medium | Signal carried (as shown in the slide) |
|---|---|
| Copper cable | Patterns of electrical pulses |
| Fibre-optic cable | Patterns of light pulses |
| Wireless | Patterns of radio transmissions |

### 4.4 Elements needed for physical delivery

The delivery of frames across local media requires:
- Physical media and associated connectors.
- A representation of bits on the medium.
- Encoding of data and control information.
- Transmitter and receiver circuitry on network devices.

## 5. Physical Layer Encoding and Encapsulation (Slide 7)

The diagram traces data as it moves down the protocol stack at the source and up the stack at the destination.

| Layer | Protocol Data Unit (PDU) shown |
|---|---|
| Application | Data |
| Presentation | Data |
| Session | Data |
| Transport | Segment |
| Network | Packet |
| Data Link | Frame |
| Physical | Bits |

### Sender-side process

1. Application produces data.
2. Transport layer places the data into a segment.
3. Network layer encapsulates it into a packet.
4. Data Link Layer encapsulates the packet into a frame, adding link-layer information.
5. Physical Layer represents the frame's bits as signals on the medium.

### Receiver-side process

1. Physical Layer receives the signals and recovers the bit sequence.
2. Data Link Layer reconstructs and processes the frame.
3. The frame's payload is passed up to the Network Layer as a packet.
4. Each higher layer processes its PDU and passes the payload upward until the application receives the data.

> [!important] PDU sequence
> **Data → Segment → Packet → Frame → Bits** at the sender. The receiving side performs the reverse process.

## 6. Physical Layer Principles (Slide 8)

The slide separates the process into three connected ideas:

1. **Layer 2 frame:** the input received from the Data Link Layer.
2. **Encoding:** mapping the frame's bit sequence into a representation suitable for transmission.
3. **Signalling:** producing the corresponding physical waveform or signal transitions.
4. **Media:** the physical path through which the signal travels.

The Physical Layer therefore handles the conversion from a Layer 2 frame's bit sequence into a signal that can propagate through the selected medium.

## 7. Signalling Bits for the Media (Slide 9)

The slide illustrates different signal properties that can be varied to represent bits:

| Property | Meaning |
|---|---|
| Varying amplitude | Change the signal's amplitude/level to represent information |
| Varying frequency | Change how rapidly the signal oscillates |
| Varying phase | Change the signal's phase position |
| Clock | A timing reference shown alongside the data signalling |

The bit-time divisions indicate that the receiver needs to interpret the signal over defined time intervals. The clock waveform illustrates the timing reference used to identify bit intervals.

> [!note] Do not mix the terms
> **Encoding** defines how bit values are represented. **Signalling** is the physical transmission of that representation through the medium.

## 8. Signalling Methods (Slide 10)

The slide explains two line-encoding methods: NRZ and Manchester encoding.

### 8.1 NRZ (Non-Return-to-Zero) Encoding

- A low voltage represents binary **0**.
- A higher voltage represents binary **1**.
- The signal stays at the selected level for the bit interval; it does not have to return to zero between successive bits.

The waveform in the slide demonstrates the voltage level changing according to the sequence of 0s and 1s.

### 8.2 Manchester Encoding

A voltage transition occurs in the middle of every bit interval:

- **0:** high-to-low transition within the bit time.
- **1:** low-to-high transition within the bit time.

The direction of the mid-bit transition identifies the bit value.

### NRZ vs Manchester

| Feature | NRZ (as described in the slide) | Manchester (as described in the slide) |
|---|---|---|
| Representation | Low level = 0; high level = 1 | Mid-bit transition direction represents the bit |
| Transition | Depends on changes in consecutive data bits | Has a transition in each bit interval |
| Timing clue | No explicit mid-bit transition rule in the slide | Mid-bit transition provides a timing reference |

> [!warning] Exam accuracy
> Memorise the direction exactly as given in this deck: **Manchester 1 = low-to-high; Manchester 0 = high-to-low.**

## 11. Key Diagrams – What to Explain in an Exam

### OSI communication diagram (Slide 3)
- End hosts have all seven OSI layers.
- Intermediate nodes in the diagram use Layers 1–3.
- Physical communication occurs over each link through Layer 1.
- The slide marks Layers 1–2 as hardware implementation and Layers 3–7 as software implementation.

### Signal and medium diagram (Slides 5, 8 and 9)
- The Data Link Layer supplies a frame/bit sequence.
- Encoding maps bits to a signal representation.
- Signalling produces amplitude, frequency or phase changes.
- The physical medium carries the electrical, optical or radio signal.

### Encapsulation diagram (Slide 7)
- Data is encapsulated down the stack.
- The PDU changes as it descends: data, segment, packet, frame, bits.
- At the receiver, bits are recovered and the PDUs are decapsulated upward.

### NRZ and Manchester waveforms (Slide 10)
- NRZ: low voltage is 0 and high voltage is 1.
- Manchester: a mid-bit transition is used; low-to-high is 1 and high-to-low is 0.

## 13. Common Exam Confusions

1. **Frame vs bits:** the Data Link Layer works with frames; the Physical Layer sends their bits as signals.
2. **Analog vs digital:** analog is continuous-valued; digital is discrete-valued.
3. **Encoding vs signalling:** encoding maps the data bits to a representation; signalling transmits that representation physically.
4. **Copper vs fibre vs wireless:** electrical pulses vs light pulses vs radio transmissions.
5. **NRZ vs Manchester:** NRZ uses voltage levels; Manchester uses the direction of a transition in the middle of each bit time.
6. **Layer numbering:** Physical is Layer 1, Data Link is Layer 2, and Network is Layer 3.
7. **Standards organisations:** do not confuse the bodies listed (ISO, IEEE, ANSI, ITU, EIA/TIA, FCC) with the separate IETF note for TCP/IP standards.
