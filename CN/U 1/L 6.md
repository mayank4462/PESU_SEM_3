# 1. Why Do We Need Layering?

Networks are **complex systems** containing many components:

- Hosts
- Routers
- Links
- Applications
- Protocols
- Hardware
- Software
- Various media

The lecture uses **airline travel** as an analogy for layering.

### Airline example

An airline journey can be divided into separate services:

```
Ticketing
   ↓
Baggage
   ↓
Gates
   ↓
Runway
   ↓
Airplane routing
```

Each layer performs its own task.

For example:

```
Ticket service
→ Ticket purchase / complaint

Baggage service
→ Baggage check / claim

Gate service
→ Boarding / unloading

Runway service
→ Takeoff / landing

Routing service
→ Airplane routing
```

### Networking idea

Similarly, networking is divided into **layers**, where each layer:

1. Performs its own internal operations.
2. Provides a service to the layer above it.
3. Uses services provided by the layer below it.

This makes complex systems easier to understand and manage.

---

# 2. Why Layering Is Useful

The lecture asks why we should use layering when designing/discussing complex systems.

### Main advantages

### 1. Modularity

Each layer has a specific responsibility.

Changes can be made to one layer without completely redesigning the entire system.

### 2. Easier maintenance

If one layer changes, the other layers can continue to work using the same service interface.

### 3. Easier design

A complex system is divided into smaller, manageable pieces.

### 4. Clear responsibilities

Each layer has clearly defined functionality.

---

# 3. Protocol Layering

The lecture describes the basic idea of layering as follows:

> Each layer implements a service via its own internal-layer actions while relying on services provided by the layer below.

Think of it like:

```
Layer N
   ↓ uses service
Layer N-1
   ↓ uses service
Layer N-2
   ↓
...
```

A layer does **not need to know all the internal details** of the layers below it.

# 8. Link Layer

The link layer handles **data transfer between neighboring network elements**.

The lecture mentions:

- Ethernet
- Wi-Fi
- 802.11
- PPP

So:

```
Node → Neighboring node
```

### Important

Don't confuse:

**Network layer:** source → destination across multiple networks

**Link layer:** one neighboring node → another neighboring node

# 19. Encapsulation

## What is encapsulation?

Encapsulation occurs when data moves **down the protocol stack**.

Each lower layer adds its own header.

Example:

```
Application:
[M]

Transport:
[Hₜ][M]

Network:
[Hₙ][Hₜ][M]

Link:
[Hₗ][Hₙ][Hₜ][M]
```

The lecture illustrates this process across pages 13–20.

---

# 20. Step-by-Step Encapsulation

Suppose application generates:

```
M
```

### Step 1 — Application

```
[M]
```

The application creates a **message**.

---

### Step 2 — Transport

Transport adds a transport header:

```
[Ht][M]
```

This becomes a:

> **Segment**

---

### Step 3 — Network

Network adds a network header:

```
[Hn][Ht][M]
```

This becomes a:

> **Datagram**

---

### Step 4 — Link

Link adds a link-layer header:

```
[Hl][Hn][Ht][M]
```

This becomes a:

> **Frame**

---

### Step 5 — Physical

The frame is transmitted as:

```
Bits
```

---

# 21. Decapsulation

Decapsulation is the **reverse process**.

It happens when data travels **up the protocol stack at the destination**.

Example:

```
Frame
 ↓
Remove Link header
 ↓
Datagram
 ↓
Remove Network header
 ↓
Segment
 ↓
Remove Transport header
 ↓
Message
 ↓
Application
```

The lecture illustrates this using the "stacked dolls" analogy.

---

# 22. Matryoshka Doll Analogy

The PDF uses **Russian/Maryoshka stacking dolls** to explain encapsulation.

Think:

```
Message
   ↓
Segment
   ↓
Datagram
   ↓
Frame
```

Each layer wraps the data with additional information.

At the destination, these layers are removed one by one.

That's **decapsulation**.

---

# 23. Headers

Each layer can add its own header.

For example:

```
Application:
[M]

Transport:
[Ht][M]

Network:
[Hn][Ht][M]

Link:
[Hl][Hn][Ht][M]
```

The receiver removes these headers in reverse order.

# 📝 4-Mark Questions

## 1. Explain the need for layering in computer networks.

**Answer:**

Computer networks are complex systems consisting of hosts, routers, links, applications, protocols, hardware and software. Layering divides this complexity into separate functional layers.

Each layer:

- Performs specific functions.
- Provides services to the layer above.
- Uses services from the layer below.
- Can be modified or maintained with limited impact on other layers.

Therefore, layering provides **modularity, simpler design and easier maintenance**.

### Network

### Link

### Physical

# 3. Explain the OSI reference model.

**Answer:**

The OSI model consists of seven layers:

```
7. Application
8. Presentation
9. Session
10. Transport
11. Network
12. Data Link
13. Physical
```

- **Application:** Network applications.
- **Presentation:** Data interpretation, encryption and compression.
- **Session:** Synchronization, checkpointing and recovery.
- **Transport:** Process-to-process communication.
- **Network:** Routing.
- **Data Link:** Neighboring-node communication.
- **Physical:** Transmission of bits.

The lecture identifies the OSI model as an ISO model introduced in the late 1970s.

# 5. Explain encapsulation with an example.

**Answer:**

When application data moves down the protocol stack, every layer adds its own control information/header.

```
Application
[M]

Transport
[Ht][M]

Network
[Hn][Ht][M]

Link
[Hl][Hn][Ht][M]

Physical
Bits
```

Thus:

```
Message
   ↓
Segment
   ↓
Datagram
   ↓
Frame
   ↓
Bits
```

This process is called **encapsulation**.

---

# 6. Explain decapsulation.

**Answer:**

At the destination, the received data moves upward through the protocol stack. Each layer removes the header added by the corresponding layer at the sender.

```
Bits
 ↓
Frame
 ↓ remove link header
Datagram
 ↓ remove network header
Segment
 ↓ remove transport header
Message
 ↓
Application
```

This reverse process is called **decapsulation**. The lecture illustrates this using the stacked-doll analogy.

---

# 7. Explain the PDU at each layer.

**Answer:**

As data moves down the Internet protocol stack, its terminology changes:

```
Application → Message
Transport   → Segment
Network     → Datagram
Link        → Frame
Physical    → Bits
```

Each layer adds its own header during encapsulation.
