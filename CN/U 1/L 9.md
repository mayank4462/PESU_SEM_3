# 1. Application Layer Overview

## What is the Application Layer?

The **Application Layer** is the top layer of the Internet protocol stack.

It provides network services directly to applications such as:

- Web
- E-mail
- Text messaging
- Social networking
- Voice over IP
- Video conferencing
- Streaming video
- Online gaming
- File sharing
- Remote login

### Important Application-Layer Protocols

|Application|Protocol|
|---|---|
|Web|HTTP|
|E-mail|SMTP|
|File transfer|FTP|
|Internet telephony|SIP|
|Web documents|HTTP|
|Streaming|SIP / RTP / HTTP etc.|
|Interactive games|Various protocols|

The lecture specifically focuses on:

- HTTP
- Application-layer protocols
- Client-server paradigm
- Peer-to-peer paradigm
- Transport-layer service models

---

# 2. Network Applications

Network applications are programs that:

- Run on different **end systems**
- Communicate with one another **over a network**
- Use application-layer protocols for communication

### Important

Network applications generally **do not need to be implemented inside network-core devices**.

The network core provides communication infrastructure, while applications run on end systems.

### Example

A web browser communicates with a web server.

```
Web Browser  <---- Internet ---->  Web Server
   Client                         Server
```

The browser and server use an application-layer protocol such as **HTTP**.

---

# 3. Client-Server Paradigm

## Server

A **server** is generally:

- Always-on
- Has a permanent IP address
- Often located in a data center
- Designed to handle requests from clients

## Client

A **client**:

- Communicates with the server
- May be intermittently connected
- May have a dynamic IP address
- Does not usually communicate directly with other clients

### Examples

- HTTP
- IMAP
- FTP
- SMTP

### Diagram

```
             Server
        Permanent IP address
              |
        ---------------
        |      |      |
      Client Client Client
```

### Key Exam Point

> **Server = always-on + permanent IP**

> **Client = intermittent connection + may have dynamic IP**

---

# 4. Peer-to-Peer (P2P) Paradigm

In a **P2P architecture**, there is **no always-on server**.

Peers communicate directly with one another.

```
Peer A <------> Peer B
  ^               ^
  |               |
  v               v
Peer C <------> Peer D
```

## Characteristics

- No always-on server
- Peers communicate directly
- A peer can request services
- A peer can provide services
- Peers may have intermittent connectivity
- Peers may change IP addresses

### Self-Scalability

A major advantage of P2P is **self-scalability**.

When a new peer joins:

1. It requests services from existing peers.
2. It can also provide services to other peers.

Therefore, the new peer contributes resources to the system.

### Example

**P2P file sharing**

Examples mentioned in the lecture:

- BitTorrent

---

# 5. Client-Server vs P2P

|Feature|Client-Server|P2P|
|---|---|---|
|Always-on server|Yes|No|
|Permanent IP server|Usually|No|
|Direct peer communication|Usually no|Yes|
|Scalability|Server can become bottleneck|Self-scalable|
|Dynamic IP|Clients may have it|Peers may have it|
|Example|HTTP, FTP, SMTP|BitTorrent|

### ⭐ Very Important

**Client-server:**

```
Client → Server
```

**P2P:**

```
Peer ↔ Peer
```

# 6. Processes Communicating

A **process** is a program that is running within a host.

### Communication on Same Host

Two processes on the same host communicate using **inter-process communication (IPC)**.

### Communication on Different Hosts

Processes on different hosts communicate by **exchanging messages**.

```
Host A                         Host B

Process A  ---- messages ----> Process B
```

---

# 7. Client Process and Server Process

### Client Process

A process that **initiates communication**.

### Server Process

A process that **waits to be contacted**.

```
Client Process
      |
      | request
      ↓
Server Process
      |
      | response
      ↓
Client Process
```

### Important

In a P2P architecture, a process can act as **both client and server**.

# 8. Sockets

A **socket** is the interface between the application process and the transport layer.

Think of a socket as a **door** through which an application sends and receives messages.

### Analogy from the lecture

> Socket is analogous to a **door**.

The application controls what goes through the door, while the transport layer provides the communication service.

```
Application
     |
   Socket
     |
Transport Layer
     |
 Network
```

### Two Sockets

For communication between two processes:

```
Process A
   |
 Socket A
   |
Internet
   |
 Socket B
   |
Process B
```

Each side has one socket.

---

# 9. Addressing Processes

A message must be delivered to the **correct process**.

An IP address alone identifies a **host**, not a particular process.

Therefore, we need:

```
IP Address + Port Number
```

### Process Identifier

A process is identified using:

**IP address + port number**

### Example

```
128.119.245.12 : 80
```

Here:

- `128.119.245.12` → IP address
- `80` → Port number

Port number identifies the process/service running on that host.

### Common Example

HTTP server:

```
IP address : 80
```

# 10. Application-Layer Protocol

An application-layer protocol defines how application processes communicate.

It specifies:

### 1. Types of Messages

Examples:

- Request
- Response

### 2. Message Syntax

Defines:

- Fields
- Structure
- Format

### 3. Message Semantics

Defines the **meaning of information contained in each field**.

### 4. Rules

Defines:

- When messages are sent
- How messages are interpreted
- How a process responds

---

# 11. Open vs Proprietary Protocols

## Open Protocols

Defined in **RFCs**.

Anyone can implement them.

Advantages:

- Interoperability
- Standardization
- Widely available

Examples:

- HTTP
- SMTP

## Proprietary Protocols

Controlled by a particular company or organization.

Example from lecture:

- Skype

### ⭐ Remember

```
Open protocol → RFC → publicly defined
Proprietary protocol → controlled by a specific organization
```

# 12. What Does an App Need from Transport Service?

Different applications require different transport-layer characteristics.

The major requirements are:

1. Data integrity
2. Throughput
3. Timing
4. Security

---

# 13. Data Integrity

Some applications require **100% reliable data transfer**.

Example:

- File transfer
- Web transactions
- E-mail

If even some data is lost, the application may not work correctly.

Other applications can tolerate some loss.

Example:

- Real-time audio/video

### Exam Point

```
File transfer → no data loss
Audio/video → some loss may be tolerated
```

---

# 14. Throughput

**Throughput** refers to the amount/rate of data that can be delivered over a network.

Some applications need a minimum throughput.

### Example

Multimedia applications require sufficient throughput to maintain quality.

Other applications are **elastic**.

### Elastic Application

An elastic application can make use of whatever throughput is available.

Examples:

- File transfer
- E-mail
- Web documents

---

# 15. Timing

Some applications are sensitive to delay.

Examples:

- Interactive games
- Internet telephony
- Video conferencing

These applications require low delay.

### Example

In an interactive game:

```
High delay → poor gaming experience
Low delay → better gaming experience
```

---

# 16. Security

Applications may require:

- Encryption
- Data integrity
- Authentication
- Confidentiality

Security is particularly important when sensitive information is transferred.

---

# 17. Common Application Requirements

|Application|Data Loss|Throughput|Time Sensitive?|
|---|---|---|---|
|File transfer/download|No loss|Elastic|No|
|E-mail|No loss|Elastic|No|
|Web documents|No loss|Elastic|No|
|Real-time audio/video|Loss tolerant|Audio/video rate|Yes|
|Streaming audio/video|Loss tolerant|Required rate|Yes|
|Interactive games|Loss tolerant|~Kbps|Yes|
|Text messaging|No loss|Elastic|No|

### ⭐ Memorize

**File transfer → Reliable + Elastic + Not time-sensitive**

**Interactive games → Loss-tolerant + Kbps + Time-sensitive**

---

# 18. TCP Service

TCP = **Transmission Control Protocol**

TCP provides:

### 1. Reliable Data Transfer

Ensures data is delivered reliably.

### 2. Flow Control

Prevents a sender from overwhelming the receiver.

```
Fast Sender → [Flow Control] → Slow Receiver
```

### 3. Congestion Control

Controls sending rate when the network becomes congested.

### 4. Connection-Oriented Service

TCP requires a connection to be established between client and server/processes.

---

# 19. What TCP Does NOT Provide

According to the lecture, TCP does **not** provide:

- Minimum throughput guarantee
- Timing guarantee
- Security guarantee
- Specific bandwidth guarantee

### Important

```
TCP = Reliable + Flow Control + Congestion Control
```

but

```
TCP ≠ Guaranteed delay
TCP ≠ Guaranteed bandwidth
TCP ≠ Built-in security
```

---

# 20. UDP Service

UDP = **User Datagram Protocol**

UDP provides an **unreliable data transfer service**.

It does not guarantee reliable delivery.

### UDP Does NOT Provide

- Reliability
- Flow control
- Congestion control
- Minimum throughput guarantee
- Security guarantee
- Connection setup

### Key Idea

UDP is **connectionless**.

```
Application
     |
    UDP
     |
 Network
```

There is no connection establishment like TCP.

---

# 21. TCP vs UDP

|Feature|TCP|UDP|
|---|---|---|
|Reliable transfer|✅|❌|
|Flow control|✅|❌|
|Congestion control|✅|❌|
|Connection-oriented|✅|❌|
|Minimum throughput|❌|❌|
|Timing guarantee|❌|❌|
|Security|❌|❌|
|Connection setup|Required|Not required|

### ⭐ Most Important Table

```
TCP → Reliable
UDP → Unreliable
TCP → Connection-oriented
UDP → Connectionless
TCP → Flow control
TCP → Congestion control
UDP → None of these
```

# 🟥 4-MARK QUESTIONS

## Q1. Explain the client-server paradigm.

**Answer:**

In the client-server paradigm:

1. A **server** is generally always-on.
2. The server usually has a **permanent IP address**.
3. Clients initiate communication by sending requests to the server.
4. Clients may be intermittently connected and may have dynamic IP addresses.

Examples include:

- HTTP
- FTP
- SMTP
- IMAP

```
Client  ───── Request ─────> Server
Client  <──── Response ───── Server
```

---

## Q2. Explain P2P architecture.

**Answer:**

P2P architecture does not depend on an always-on central server.

Characteristics:

1. Peers communicate directly with each other.
2. A peer can act as both client and server.
3. Peers may have intermittent connectivity.
4. P2P systems are self-scalable because new peers contribute resources.

Example:

**BitTorrent**

---

## Q3. Differentiate between client-server and P2P architectures.

**Answer:**

|Client-Server|P2P|
|---|---|
|Has always-on server|No always-on server|
|Server generally has permanent IP|Peers may have dynamic IP|
|Clients request services|Peers request and provide services|
|Server can become bottleneck|Self-scalable|
|Example: HTTP|Example: BitTorrent|

---

## Q4. Explain sockets.

**Answer:**

A socket is the interface between an application and the transport layer.

It can be viewed as a **door** through which an application sends and receives messages.

For communication:

```
Application
     |
   Socket
     |
Transport
     |
 Internet
     |
Transport
     |
   Socket
     |
Application
```

There is one socket at each communicating process.

## Q5. Explain the four transport-service requirements of applications.

**Answer:**

### 1. Data Integrity

Some applications require reliable transfer without data loss.

Example: File transfer.

### 2. Throughput

Some applications require sufficient data-transfer rate.

Example: Multimedia applications.

### 3. Timing

Some applications require low delay.

Example: Interactive gaming.

### 4. Security

Applications may require encryption and data integrity.

---

## Q6. Explain TCP services.

**Answer:**

TCP provides:

### 1. Reliable Data Transfer

Ensures reliable delivery of data.

### 2. Flow Control

Prevents the sender from overwhelming the receiver.

### 3. Congestion Control

Controls transmission when the network becomes congested.

### 4. Connection-Oriented Service

A connection must be established before data transfer.

TCP does **not** guarantee minimum throughput, timing, or security.

---

## Q7. Explain UDP services.

**Answer:**

UDP provides an unreliable and connectionless data-transfer service.

UDP does not provide:

- Reliable transfer
- Flow control
- Congestion control
- Minimum throughput guarantee
- Timing guarantee
- Security guarantee
- Connection setup

UDP is useful when applications can tolerate some data loss or need low overhead.

---

## Q8. Explain the components of an application-layer protocol.

**Answer:**

An application-layer protocol specifies:

1. **Message types** — request, response, etc.
2. **Message syntax** — structure and fields of messages.
3. **Message semantics** — meaning of each field.
4. **Rules** — when messages are sent and how they are responded to.
