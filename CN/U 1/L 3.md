# PART 1 — MUST KNOW

# 1. Network Core

The **network core** consists of a **mesh of interconnected routers**.

### Main functions

The network core:

- Contains interconnected routers.
- Uses packet switching.
- Breaks application-layer messages into packets.
- Forwards packets from one router to the next.
- Transmits packets across links toward the destination.

### Key definition

> **Network core = mesh of interconnected routers.**

---

# 2. Packet Switching

In packet switching:

> Hosts break application-layer messages into **packets**.

Each packet:

- Has a fixed length, **L bits** in the example.
- Travels from one router to the next.
- Is transmitted at a link transmission rate **R**.
- Can be transmitted at full link capacity.

### Basic process

```
Source Host
    ↓
Message
    ↓
Break into packets
    ↓
Packet 1
Packet 2
Packet 3
    ↓
Router
    ↓
Router
    ↓
Destination
```

---

# 3. Packet Transmission Delay

This is a **very important formula**.

If:

- Packet length = **L bits**
- Transmission rate = **R bits/sec**

Then:

dtrans=LRd_{trans} = \frac{L}{R}

### Meaning

Transmission delay is the:

> **Time needed to push all L bits of a packet into the link.**

### Remember

```
Transmission Delay = L / R
```

---

# 4. One-Hop Numerical Example

The PDF gives:

- **L = 10 Kbits**
- **R = 100 Mbps**
- One-hop transmission delay = **0.1 msec**

Let's verify:

L=10,000 bitsL = 10,000\ bits R=100,000,000 bits/secR = 100,000,000\ bits/sec dtrans=10,000100,000,000d_{trans} = \frac{10,000}{100,000,000} =0.0001s=0.0001s =0.1ms=0.1ms

### Exam trick

Always convert:

- Kbits → bits
- Mbps → bits/sec
- Gbps → bits/sec

before applying:

LR\frac{L}{R}

---

# 5. Store-and-Forward

A router uses **store-and-forward** behavior.

### Meaning

The **entire packet must arrive at the router before it can be transmitted onto the next link**.

```
Source
  │
  │ packet
  ↓
Router
  │
  │ waits for entire packet
  ↓
Next link
```

### Important

If the packet has not completely arrived:

> The router cannot forward the entire packet.

---

# 6. End-to-End Delay

For the simple example in the PDF:

- Transmission delay = **L/R**
- Store-and-forward is used.
- Propagation delay is assumed to be zero for the short example.

For multiple links, transmission delays accumulate.

For **two links**:

dend−end=LR1+LR2d_{end-end} = \frac{L}{R_1}+\frac{L}{R_2}

If both links have the same rate R:

dend−end=2LRd_{end-end} = \frac{2L}{R}

The slide emphasizes that end-to-end delay can be more than a single transmission delay.

---

# 7. Packet Queuing and Loss

Suppose packets arrive at a router faster than they can leave.

Then packets begin to **wait in a queue**.

### Example from the slide

One link:

R=100 MbpsR = 100\ Mbps

Another/output link:

R=1.5 MbpsR = 1.5\ Mbps

Packets arriving faster than the output link can transmit will queue.

```
Packets
↓↓↓↓↓↓
[Router]
   ↓
 Queue → → → Output link
             R = 1.5 Mbps
```

### What happens?

1. Packets arrive.
2. Output link cannot transmit them quickly enough.
3. Packets wait in the queue.
4. Queue grows.
5. If the router's buffer becomes full, packets can be **dropped/lost**.

---

# 8. Packet Queuing and Loss

### Packet queuing

Occurs when:

> Arrival rate exceeds the transmission rate of the output link for some period of time.

### Packet loss

Occurs when:

> The router's buffer/memory becomes full and incoming packets have nowhere to wait.

### Important relationship

```
Arrival rate > Output transmission rate
                 ↓
              Queue
                 ↓
          Buffer becomes full
                 ↓
            Packet loss
```

---

# 9. Two Key Network Core Functions

The PDF identifies two major network-core functions:

## 1. Routing

**Global action**

Determines the source-to-destination path taken by packets.

### Routing algorithm

Determines the path through the network.

---

## 2. Forwarding

**Local action**

Moves an arriving packet from a router's input link to the appropriate output link.

### Easy difference

> **Routing = where should the packet go?**

> **Forwarding = move the packet to the correct output link.**

---

# 10. Routing vs Forwarding

|Routing|Forwarding|
|---|---|
|Global action|Local action|
|Determines source-destination path|Moves arriving packet to appropriate output link|
|Uses routing algorithms|Uses forwarding table|
|Decides overall route|Performs immediate packet movement|

### Exam memory trick

```
ROUTING
= PATH DECISION

FORWARDING
= PACKET MOVEMENT
```

# 11. Circuit Switching

Circuit switching uses **end-end resources reserved for the duration of the communication**.

### Key characteristics

- Resources are reserved.
- Resources are dedicated.
- A circuit is established before communication.
- Capacity is reserved for the call/session.

The PDF gives traditional telephone networks as an example.

---

# 12. Circuit Switching — Dedicated Resources

In circuit switching:

> Each call gets a dedicated circuit.

The slide shows a network where each call gets its own circuit.

### Important consequence

The allocated bandwidth remains reserved even when the user is not actively sending data.

This can result in **wasted capacity**.

---

# 13. Packet Switching vs Circuit Switching

This is a **very high-probability exam question**.

|Packet Switching|Circuit Switching|
|---|---|
|Connectionless in the slide's comparison|Connection-oriented|
|Designed for data|Designed for voice|
|Flexible|Less flexible|
|No fixed dedicated path/resources|Resources reserved|
|Packets can be routed dynamically|Dedicated circuit|
|Bandwidth is dynamically shared|Bandwidth is saved/reserved|
|Transmission can be bursty|Continuous/dedicated allocation|
|Packet delay/queueing can occur|Dedicated resources provide predictable allocation|

### Most important distinction

**Packet switching:**

> Resources are shared dynamically.

**Circuit switching:**

> Resources are reserved for a connection.

---

# 14. Circuit Switching and Wasted Capacity

The PDF explains that circuit switching reserves a fixed slice of bandwidth for the entire call.

In typical voice calls, only around **50–60% of the time** may involve actual talking, according to the slide.

Therefore, the reserved capacity can remain unused during silent periods.

### Example

```
Circuit capacity
████████████████████

Talking:
████████████

Silence:
░░░░░░░░░░░░
```

The reserved resource remains allocated even during silence.

---

# 15. Statistical Multiplexing

Packet switching uses **statistical multiplexing**.

### Definition

Statistical multiplexing dynamically allocates bandwidth to sources **as needed**.

Instead of reserving a fixed portion for every source:

```
Source A ─┐
Source B ─┼── Shared link
Source C ─┤
Source D ─┘
```

Sources use the link when they actually have data to send.

### Why is this useful?

It avoids wasting bandwidth when a source is inactive.

---

# 16. FDM — Frequency Division Multiplexing

FDM stands for:

> **Frequency Division Multiplexing**

In FDM:

- Electromagnetic frequencies are divided into **frequency bands**.
- Each call/user gets its own frequency band.
- Each can transmit at the maximum rate of that band.

### Diagram idea

```
Frequency
↑
| User 4 █████
| User 3 █████
| User 2 █████
| User 1 █████
+----------------→ Time
```

Each user receives a separate frequency band.

---

# 17. TDM — Time Division Multiplexing

TDM stands for:

> **Time Division Multiplexing**

In TDM:

- Time is divided into **frames**.
- Each frame is divided into **time slots**.
- Each user is allocated a periodic time slot.

### Diagram

```
Time →
┌──┬──┬──┬──┐
│A │B │C │D │
└──┴──┴──┴──┘
   Frame

Next frame:
┌──┬──┬──┬──┐
│A │B │C │D │
└──┴──┴──┴──┘
```

Each user gets a fixed time slot.

---

# 18. FDM vs TDM

|FDM|TDM|
|---|---|
|Divides frequency|Divides time|
|Each user gets frequency band|Each user gets time slot|
|User transmits using its frequency|User transmits during its assigned slot|
|Frequency-oriented|Time-oriented|

### Easy memory:

**FDM → Frequency**

**TDM → Time**

---

# 19. Why Packet Switching?

The PDF asks why packet switching is preferred for data.

### Circuit switching

Circuit switching reserves a fixed slice of bandwidth.

But data traffic is often:

> **Bursty**

That means a source may send a lot of data at one moment and very little or nothing at another.

### Packet switching

Packet switching allows bandwidth to be shared dynamically.

Therefore:

> Packet switching is more efficient for bursty data traffic.

---

# 20. Is Packet Switching a "Slum Dweller"?

The slide asks:

> Is packet switching a "slam dunk winner"?

The answer is **not necessarily**.

### Advantages

- Great for bursty data
- Efficient resource sharing
- No fixed reservation
- Simple setup
- Better utilization when sources are inactive

### Disadvantages

- Packet delay is possible.
- Packet loss is possible.
- Queueing can occur.
- Congestion can occur.
- Reliable data transfer and congestion control may need additional protocols.

### Important

The slide says packet switching can have:

> **Excessive congestion possible: packet delay and loss due to buffer overflow.**

# 22. Why Not Connect Every ISP Directly?

Suppose there are millions of access ISPs.

Connecting every access ISP directly to every other ISP does not scale.

The number of connections would grow approximately as:

O(N2)O(N^2)

where **N** is the number of ISPs.

### Key idea

```
Many ISPs
   ↓
Directly connecting every pair
   ↓
O(N²) connections
   ↓
Doesn't scale
```

Therefore, a hierarchical/interconnected structure is used.

---

# 23. Global Transit ISP

The global ISP provides connectivity between access networks.

The access ISP is the **customer**.

The global ISP is the **provider**.

# PART 4 — 4-MARK QUESTIONS

# Q1. Explain packet switching.

### Answer:

In packet switching, a host takes an application-layer message and **breaks it into packets**.

Each packet:

1. Is transmitted across a link.
2. Travels from router to router.
3. Is forwarded toward its destination.
4. Shares network resources with packets from other users.

If a packet has length **L bits** and the link transmission rate is **R bits/sec**, the transmission delay is:

dtrans=LRd_{trans}=\frac{L}{R}

Packet switching is efficient for bursty data because bandwidth can be shared dynamically.

However, it can experience:

- Queueing delay
- Congestion
- Packet loss

---

# Q2. Explain packet queuing and packet loss.

### Answer:

Packets are placed in a router's output queue when the **arrival rate exceeds the output link's transmission rate**.

```
High arrival rate
       ↓
   [ Router ]
       ↓
   ┌────────┐
   │ Queue  │
   │Packets │
   └────────┘
       ↓
Output link
```

If packets continue arriving faster than they can be transmitted:

1. Queue length increases.
2. Router buffer fills.
3. Once the buffer is full, packets can be dropped.
4. This results in **packet loss**.

Thus:

> **Arrival rate > output rate → queueing → buffer overflow → packet loss**

---

# Q3. Explain routing and forwarding.

### Answer:

The network core has two important functions:

### Routing

Routing is a **global action**.

It determines the complete source-to-destination path using a routing algorithm.

### Forwarding

Forwarding is a **local action**.

It moves an arriving packet from the router's input link to the appropriate output link.

```
Routing
= Determines PATH

Forwarding
= Moves PACKET to OUTPUT LINK
```

# Q4. Explain circuit switching.

### Answer:

Circuit switching reserves **end-to-end resources** for the duration of a communication.

It is traditionally used for telephone networks.

Characteristics:

- Connection-oriented
- Dedicated resources
- Reserved bandwidth
- Dedicated circuit
- Resources remain allocated during the connection

A disadvantage is that reserved resources may remain unused during periods when no data is being transmitted.

# Q5. Compare packet switching and circuit switching.

### Answer:

|Packet Switching|Circuit Switching|
|---|---|
|Resources are shared dynamically|Resources are reserved|
|Suitable for bursty data|Traditionally suited to voice|
|No fixed dedicated circuit|Dedicated circuit|
|Queueing possible|Reserved capacity|
|Packet loss possible during congestion|Dedicated resources|
|Efficient when users are intermittently active|Can waste capacity during silence|

### Conclusion:

Packet switching generally makes more efficient use of resources for **bursty data**, but congestion can introduce delay and loss.

# Q6. Explain FDM and TDM.

### Answer:

### FDM — Frequency Division Multiplexing

The available frequency spectrum is divided into separate frequency bands.

Each user receives a particular frequency band.

```
Frequency
↑
│ User D
│ User C
│ User B
│ User A
└──────────→ Time
```

### TDM — Time Division Multiplexing

Time is divided into frames, and each frame is divided into time slots.

Each user receives a periodic time slot.

```
Time →
┌───┬───┬───┬───┐
│ A │ B │ C │ D │
└───┴───┴───┴───┘
```

### Main difference:

> **FDM divides frequency; TDM divides time.**

# Q7. Why is packet switching useful for bursty data?

### Answer:

Circuit switching reserves a fixed amount of bandwidth for a connection, even when the user is not transmitting.

Data communication is often **bursty**, meaning the amount of data being sent varies over time.

Packet switching uses **statistical multiplexing**, allowing active users to dynamically share available bandwidth.

Therefore:

- Less bandwidth is wasted.
- Resources are shared efficiently.
- Multiple users can use the same link.

However, excessive traffic can cause **queueing, delay and packet loss**.

---

# Q8. Explain why directly connecting every access ISP does not scale.

### Answer:

Suppose there are **N access ISPs**.

If every ISP directly connects to every other ISP, the number of connections grows approximately as:

O(N2)O(N^2)

As N becomes very large, the number of required connections becomes impractical.

Therefore, the Internet uses structures involving:

- Global ISPs
- Regional ISPs
- Access ISPs
- IXPs
- Peering links
- Content provider networks

This allows the Internet to scale much better.

---

# Q9. Explain the role of an IXP.

### Answer:

An **Internet Exchange Point (IXP)** is a location where different networks/ISPs connect and exchange traffic.

### Benefits:

1. Enables direct traffic exchange.
2. Reduces dependence on upstream providers.
3. Can reduce the distance traffic travels.
4. Can reduce delay and improve efficiency.

```
ISP A ───── IXP ───── ISP B
```

# Q11. Explain how the Internet is structured as a network of networks.

### Answer:

The Internet consists of many interconnected networks.

A simplified structure contains:

1. **Access ISPs** — connect end users.
2. **Regional ISPs** — connect groups of access networks.
3. **Tier 1/global ISPs** — provide large-scale connectivity.
4. **IXPs** — allow networks to exchange traffic.
5. **Peering links** — directly connect networks.
6. **Content provider networks** — provide services/content close to users.

```
Content Providers
       │
    Tier 1 ISPs
       │
      IXP
       │
 Regional ISPs
       │
  Access ISPs
       │
    End Users
```

The actual Internet is more complex and does not follow a perfectly rigid hierarchy.

# Q12. Explain CDNs and why Netflix uses them.

### Answer:

A **Content Delivery Network (CDN)** places copies of popular content at locations close to access networks/users.

Without a CDN:

```
User → Long-distance Internet → Far-away server
```

This can produce larger end-to-end delays.

With a CDN:

```
User → Nearby CDN server
```

The content travels a shorter distance.

The PDF mentions:

- Netflix Open Connect
- Akamai
- Cloudflare
- Google Global Cache

### Main advantage

> **CDNs bring content closer to users, reducing delivery delay.**
