# 1. Web and HTTP

## Web Page

A web page consists of **objects**.

Examples of objects:

- HTML file
- JPEG image
- GIF image
- Java applet
- Audio file

Each object can be stored on a **different Web server**.

### Web Page Address

A web page is identified using a **URL**.

Example:

```
www.someschool.edu/someDept/pic.gif
```

A URL consists of:

```
Host name + Path name
```

Example:

```
www.someschool.edu  → Host name

/someDept/pic.gif   → Path name
```

### ⭐ Exam Point

A single web page may contain **multiple objects**, and those objects can be stored on different servers.

---

# 2. HTTP

## HTTP = HyperText Transfer Protocol

HTTP is the **Web's application-layer protocol**.

It follows the:

```
Client / Server model
```

### Client

The client is typically a:

- Web browser
- Firefox
- Safari
- Chrome etc.

The browser:

1. Sends HTTP requests.
2. Receives HTTP responses.
3. Displays the Web objects.

### Server

The Web server:

1. Receives HTTP requests.
2. Sends HTTP responses containing requested objects.

Examples of Web servers:

- Apache
- IIS

### HTTP Standard

The lecture specifies HTTP in:

```
RFC 1945
RFC 2616
```

---

# 3. HTTP Uses TCP

HTTP uses **TCP**.

Basic process:

```
Browser                         Server

   |                              |
   |---- TCP connection --------->|
   |                              |
   |---- HTTP Request ----------->|
   |<--- HTTP Response -----------|
   |                              |
```

### Important Steps

1. Client initiates TCP connection.
2. A socket is created to the server.
3. Server accepts the TCP connection.
4. HTTP messages are exchanged.
5. TCP connection is eventually closed depending on HTTP type.

### Default HTTP Port

```
HTTP → Port 80
```

⭐ **Very important MCQ**

---

# 4. HTTP is Stateless

HTTP is described as **stateless**.

> The server does not maintain information about past client requests.

Example:

```
Request 1 → Server
Request 2 → Server
Request 3 → Server
```

The server does not inherently maintain a history of these requests.

### Why is this useful?

Statelessness makes HTTP simpler because the server does not need to maintain state for every client request.

### ⭐ Exam Trap

**HTTP = stateless**

Do NOT confuse:

```
HTTP stateless
TCP connection-oriented
```

These describe different things.

---

# 5. Two Types of HTTP Connections

There are two important types:

1. **Non-persistent HTTP**
2. **Persistent HTTP**

---

# 6. Non-Persistent HTTP

In non-persistent HTTP:

> **At most one object is sent over one TCP connection.**

After the object is sent, the TCP connection is closed.

### Process

```
TCP connection
      ↓
Request one object
      ↓
Receive object
      ↓
Close TCP connection
```

If a page contains multiple objects, multiple TCP connections are required.

---

# 7. Non-Persistent HTTP Example

Suppose a web page contains:

```
1 HTML file
10 JPEG images
```

Total:

```
11 objects
```

For non-persistent HTTP:

```
1 TCP connection → HTML
1 TCP connection → JPEG 1
1 TCP connection → JPEG 2
...
1 TCP connection → JPEG 10
```

Therefore:

```
11 TCP connections
```

---

# 8. Persistent HTTP

In persistent HTTP:

> The TCP connection remains open after the server sends a response.

Multiple objects can be transferred through the **same TCP connection**.

```
TCP connection
      ↓
Object 1
      ↓
Object 2
      ↓
Object 3
      ↓
Object 4
      ↓
TCP connection closed
```

### Advantage

It avoids repeatedly establishing TCP connections.

---

# 9. Non-Persistent vs Persistent HTTP

|Feature|Non-Persistent|Persistent|
|---|---|---|
|TCP connection|One per object|Can serve multiple objects|
|Connection stays open|❌|✅|
|Multiple objects on same connection|❌|✅|
|TCP overhead|Higher|Lower|
|Performance|Slower|Faster|

### ⭐ Memorize

```
Non-persistent → 1 object / TCP connection

Persistent → Multiple objects / same TCP connection
```

The lecture gives an example where the user enters:

```
www.someschool.edu/someDepartment/home.index
```

The base HTML file contains references to **10 JPEG images**.

### Steps

### Step 1

HTTP client initiates a TCP connection to the HTTP server.

```
Client → TCP connection → Server
```

The server is listening on:

```
Port 80
```

---

### Step 2

HTTP client sends an HTTP request containing the URL.

```
GET /someDepartment/home.index
```

---

### Step 3

HTTP server receives the request.

It creates an HTTP response containing the requested object.

---

### Step 4

The server closes the TCP connection.

---

### Step 5

The client receives the response containing the HTML file.

The browser parses the HTML.

It discovers references to **10 JPEG objects**.

The process is repeated for each JPEG image.

# 11. RTT

## RTT = Round Trip Time

RTT is:

> The time for a small packet to travel from client to server and back.

```
Client ─────────→ Server
       ←─────────
```

That complete trip is one RTT.

---

# 12. HTTP Response Time

For non-persistent HTTP, the approximate response time per object is:

```
2 RTT + file transmission time
```

Why?

```
1 RTT → Establish TCP connection

1 RTT → HTTP request reaches server and response begins

+ transmission time → File transferred
```

Therefore:

```
HTTP response time
= 2 RTT + file transmission time
```

### ⭐ Very Important Formula

```
Non-persistent HTTP:

Total time = 2RTT + transmission time
```

---

# 13. Persistent HTTP — Without Pipelining

In persistent HTTP without pipelining:

- TCP connection is opened once.
- Multiple objects can use the same connection.
- Requests are sent one after another.
- The next request is generally made after receiving the previous response.

### For a page with:

```
1 HTML file
6 images
```

Total objects:

```
7
```

Time:

```
1 RTT → TCP connection

1 RTT → HTML request/response

6 RTT → six image request/response cycles
```

Therefore:

```
Total = 8 RTT + transmission times
```

The lecture's numerical example gives:

```
RTT = 80 ms
```

and concludes:

```
8 × 80 ms = 640 ms
```

So:

```
Answer = 0.64 s
```

when transmission time is negligible.

---

# 14. Persistent HTTP with Pipelining

**Pipelining** allows multiple HTTP requests to be sent without waiting for each individual response.

Example:

```
Request 1 ──→
Request 2 ──→
Request 3 ──→
Request 4 ──→

       Server
```

The client can request multiple objects together over an existing TCP connection.

### Advantage

Pipelining significantly reduces response time.

---

# 15. Connection Management in HTTP

The lecture compares:

### Short-lived connections

```
Establish
   ↓
Request
   ↓
Response
   ↓
Close
```

### Persistent connection

```
Establish
   ↓
Request → Response
   ↓
Request → Response
   ↓
Request → Response
   ↓
Close
```

### Key Difference

```
Non-persistent → connection closed after each object

Persistent → connection reused
```

# 20. GET Method

The **GET** method requests an object from the server.

Example:

```
GET /index.html HTTP/1.1
```

> Give me the object located at `/index.html`.

# 21. POST Method

The **POST** method is commonly used when a web page contains **form input**.

The user's form data is sent to the server in the HTTP POST request.

Example:


The data is carried in the **request body**.

# 22. HEAD Method

The **HEAD** method requests headers for an object **without requesting the object itself**.

In other words:

```
GET → headers + object

HEAD → headers only
```

### ⭐ Important MCQ

HEAD is useful when you want information about an object without downloading the object.

# 33. HTTP Numerical Problems

These are **very important for 4-mark questions**.

## Case 1 — Non-Persistent HTTP

If:

- Number of objects = `N`
- RTT = `R`
- Transmission time = negligible

Then:

```
Total time = 2N × RTT
```

Why?

Each object requires:

```
1 RTT → TCP establishment
1 RTT → request/response
```

So:

```
2 RTT/object
```

Therefore:

```
N objects → 2N RTT
```

---

# 34. Example

Suppose:

```
HTML file = 1
Images = 6
RTT = 80 ms
```

Total objects:

```
N = 7
```

For non-persistent HTTP:

```
Total = 2 × 7 × 80 ms

= 1120 ms

= 1.12 seconds
```

This matches the numerical pattern shown in the lecture.

---

# 35. Persistent HTTP Without Pipelining

For:

```
1 HTML + 6 images
```

The lecture calculates:

```
1 RTT → TCP establishment

1 RTT → HTML

6 RTT → images
```

Therefore:

```
Total = 8 RTT
```

With:

```
RTT = 80 ms
```

```
8 × 80
= 640 ms
= 0.64 seconds
```

---

# 36. Performance Comparison

For the same example:

```
1 HTML + 6 images
RTT = 80 ms
```

|Method|RTTs|Time|
|---|---|---|
|Non-persistent HTTP|14 RTT|1120 ms|
|Persistent HTTP|8 RTT|640 ms|
|Persistent + pipelining|3 RTT|240 ms|

The lecture's performance table highlights the substantial improvement from persistent HTTP and especially pipelining.

### ⭐ Remember

```
Non-persistent > Persistent > Persistent + Pipelining
```

in terms of response time.

# 🟨 2-MARK QUESTIONS

## Q1. What is HTTP?

**Answer:**

HTTP stands for **HyperText Transfer Protocol**. It is an application-layer protocol used for communication between Web clients and Web servers.

---

## Q2. What is a Web page?

**Answer:**

A Web page consists of multiple **objects**, such as HTML files, images, audio files, etc. These objects may be stored on different Web servers.

---

**Answer:**

A URL identifies the location of a Web resource. It contains a **host name** and a **path name**.

**Answer:**

HTTP is called stateless because the server does not maintain information about previous client requests.

**Answer:**

Non-persistent HTTP uses a separate TCP connection for each object. The TCP connection is closed after the object is transferred.

Persistent HTTP keeps the TCP connection open so that multiple objects can be transferred using the same connection.

---

**Answer:**

RTT or **Round Trip Time** is the time required for a small packet to travel from the client to the server and back to the client.

---

**Answer:**

HTTP pipelining allows the client to send multiple requests over an existing persistent TCP connection without waiting for each response individually.

---

**Answer:**

GET is an HTTP method used by a client to request an object from the server.

## Q11. What is the HEAD method?

HEAD requests the headers of an object without requesting the actual object itself.

## Q12. What is HTTP status code 404?

**404 Not Found** indicates that the requested object/resource was not found on the server.

# 🟥 4-MARK QUESTIONS

## Q1. Explain non-persistent HTTP.

**Answer:**

In non-persistent HTTP:

1. A TCP connection is established for each object.
2. The client sends an HTTP request.
3. The server sends the requested object.
4. The TCP connection is closed.

If a page contains `N` objects, approximately `N` TCP connections are required.

For each object:

```
1 RTT → TCP connection
1 RTT → HTTP request/response
```

Therefore:

```
Time ≈ 2RTT + transmission time
```

---

# Q2. Explain persistent HTTP.

**Answer:**

In persistent HTTP:

1. A TCP connection is established.
2. Multiple HTTP objects can be transferred through the same connection.
3. The connection remains open after individual objects are transferred.
4. The connection is closed after the required communication is completed.

### Advantages

- Fewer TCP connections
- Lower connection-establishment overhead
- Faster page loading
- Better performance

---

# Q3. Differentiate between persistent and non-persistent HTTP.

**Answer:**

|Non-Persistent|Persistent|
|---|---|
|One object per TCP connection|Multiple objects per TCP connection|
|Connection closes after object|Connection remains open|
|More TCP overhead|Less TCP overhead|
|Higher response time|Lower response time|
|Less efficient|More efficient|

---
